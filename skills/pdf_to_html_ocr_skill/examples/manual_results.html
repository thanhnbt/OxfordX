Hai mô hình phổ biến trên thế giới

Model-as-a-Service hay Token Factory?

Hai kiến trúc hạ tầng đang cạnh tranh trên giá thành của token/s.
Pattern 01 • Software layer
Model-as-a-Service
MaaS • "Bán quyền truy cập trí thông minh"
Nhà cung cấp sở hữu và host model độc quyền/mở, đóng gói qua REST API. Đơn vị bán = access + capability. Hạ tầng GPU chỉ là chi tiết ẩn.
Đặc trưng
TÍNH PHÍ
Per-token, phân biệt input/output
TỐI ƯU
Chất lượng output, đa năng, context dài
THÔNG LƯỢNG
50–200 tokens/s (GPT-4o, Sonnet 4.5)
HẠ TẦNG
Ẩn — NVIDIA H100/H200 GPU cluster
Người chơi tiêu biểu
OpenAI • Anthropic • Google DeepMind • Mistral • DeepSeek
Pattern 02 • Hardware layer
Token Factory
"Sản xuất token với chi phí thấp nhất"
Hạ tầng chuyên dụng cho inference — silicon custom (LPU, WSE), tối ưu throughput/watt. Chạy được nhiều model open-source, đơn vị bán = tốc độ + volume.
Đặc trưng
TÍNH PHÍ
Rẻ hơn/token • gói theo throughput tier
TỐI ƯU
Latency cực thấp, tokens/second cực cao
THÔNG LƯỢNG
Groq 476 t/s • Cerebras 3,000 t/s
HẠ TẦNG
Lộ diện — LPU, Wafer-Scale Engine
Người chơi tiêu biểu
Groq (LPU) • Cerebras (WSE-3) • SambaNova • NVIDIA AI Factory
Kinh tế học hội tụ: MaaS chạy trên Token Factory • Token Factory host MaaS • và biên giới đang mờ dần.

Phần 2 • Kinh tế học Tokens 08 / 17
Chi phí ẩn • Nợ kỹ thuật

Vibe coding có thể tốn chi phí rất lớn — 4 vấn đề gây tốn Tokens.

01 • Thuế Thăm dò
Exploration Tax
Chi phí "trả cho việc AI hiểu sai" — mỗi lần AI tạo code sai hướng, bạn vẫn bị tính token cho cả input + output không dùng đến.
Tác động
30-50% ngân sách "chìm"
02 • Phình ngữ cảnh
Context Bloat
Agent tự động quét toàn repo mỗi lần trả lời. Việc "đọc" mã này thường chiếm phần lớn token đầu vào — cho một câu hỏi đơn lẻ.
Tác động
60–70% input tokens
03 • Nợ kỹ thuật
Frankenstein Code
Kiến trúc chắp vá từ các yêu cầu rời rạc, không có ý định thiết kế xuyên suốt → refactor tương lai đắt gấp nhiều lần.
Tác động
Chi phí sửa gấp 5–10 lần
04 • Session mất kiểm soát
Runaway Session
Session dài lê thê không clear/compact — lịch sử hội thoại tích tụ, mỗi lượt tiếp theo trả phí cho toàn bộ quá khứ.
Tác động
Chi phí tăng theo hàm mũ

# Kỹ thuật Cơ chế cốt lõi Tiết kiệm
01 Code Knowledge Graph Index cấu trúc project → agent tra graph thay vì đọc file (case: giảm 120×) ↓ Đến 120×
02 RAG thay Full-Context Vector search truy xuất ~1K token liên quan thay vì nhồi 100K cả codebase ↓ 10–50×
03 Batch API + Prompt Cache Chấp nhận trễ ≤24h cho -50%, kết hợp cache cho -95% (Anthropic/OpenAI) ↓ 95%
04 Prompt Caching "Burst coding" giữ cache "warm" — cache read $0.30 vs input $3 (Claude) ↓ 90%
05 Semantic Caching Cache theo ý nghĩa (vector embedding) → reuse cho query tương đương ↓ 40–86%
06 Free-Tier Routing Prototype trên Gemini/Groq/OpenRouter free → prod trên paid có kiểm soát ↓ Đến 100%*
07 Model Cascading Thử Haiku/Flash trước; fallback lên Sonnet/Opus chỉ khi confidence thấp ↓ 40–70%
08 Sub-agents Delegation Giao dò tìm/research cho sub-agent context riêng, chỉ trả về kết quả cô đọng ↓ 20–80%
09 LLMLingua Compression Small LM lọc token dư trong prompt — nén ngữ nghĩa 3–20× (Microsoft) ↓ 3–20×
10 Model Routing (Task-based) DeepSeek Flash cho boilerplate, Opus cho kiến trúc — phân luồng theo độ khó ↓ 60–80%
11 Structured Output tối giản Field names ngắn (id thay customer_identifier) • StructLM giảm 46% ↓ 30–50% output
12 Session Discipline (/clear /compact) Dọn "dead weight" khỏi lịch sử; batch related changes trong 1 session ↓ 30–50%
13 Output Length Control Set max_tokens chặt • "concise" • tránh giải thích thừa (output đắt 5×) ↓ 20–40%
14 Lean Configuration CLAUDE.md / .cursorrules dưới 50 dòng — mọi ký tự nhân với số request ↓ 10–25%
15 30-second Planning Mode Buộc AI outline kế hoạch trước khi code → giảm exploration tax ↓ 15–30%

Hai kỷ luật cốt lõi

Context quản trị bộ nhớ, Harness ràng buộc hành vi.

Agent = Model + Harness
Kỷ luật 01
Context Engineering
"Nghệ thuật đưa đúng thông tin, ở đúng lượng, vào đúng vị trí."
Trọng tâm
• Chọn lọc file/section liên quan (repo-map, AST, RAG)
• Nén ngữ nghĩa (LLMLingua, prompt compression)
• Quản trị session lifecycle (/clear, /compact)
• Giữ cache "warm" — burst coding
Kỷ luật 02
Harness Engineering
"Bộ khung công cụ, ràng buộc và vòng phản hồi bao quanh model."
Trọng tâm
• Tool selection (ast-grep thay grep, typed tools trước)
• Feedback loops (test, lint, type-check tự động)
• Sub-agents với context riêng, trả về cô đọng
• Structured output ràng buộc format

Kỷ luật cấp process

Viết spec tiết kiệm nhiều token hơn với kỹ thuật viết prompt.

Spec-Driven Development (SDD) đảo ngược quan hệ: spec là source of truth, code là artifact sinh ra và verify được. GitHub, AWS, Anthropic đều chuẩn hoá lại workflow theo hướng này trong 2026.
--- Workflow 4 giai đoạn • GitHub Spec Kit
Specify → Plan → Tasks → Implement
01 • /specify
Specify
Mô tả WHAT + WHY, không đề cập HOW. Cụ thể acceptance criteria.
02 • /plan
Plan
Tech stack, architecture, constraints. Human review + approve trước khi qua bước 3.
03 • /tasks
Tasks
Chia task nhỏ, có dependency graph, mỗi task <200 dòng code, testable độc lập.
04 • /implement
Implement
AI code từ tasks đã lock. Context tối thiểu, kết quả deterministic.
RULE Không qua giai đoạn N+1 nếu giai đoạn N chưa được human approve. Cắt vòng lặp "AI đoán sai" từ gốc.

3 nguyên tắc vàng

Vibe coding tăng tốc sáng tạo — nhưng đòi hỏi kỷ luật.

01
Kiến trúc trước tiên
Plan-mode 30 giây tiết kiệm 30 phút debug.
Buộc AI vẽ kế hoạch trước khi viết code. Cost planning = cost engineering. Không có phase design, không có Frankenstein code.
02
